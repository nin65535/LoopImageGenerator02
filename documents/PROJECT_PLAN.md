## 1. 目的と位置付け

**参考画像を起点に、ユーザーがプロンプトを書かず、「好き／嫌い」を選ぶだけで画像探索を繰り返せるアプリ**を作る。V1の初回プロンプト入力を廃止する。V2はComfyUI APIを利用するローカルラッパーであり、画像生成モデルやタグ付けモデル自体は開発しない。

## 2. 基本フロー

1. 新規プロジェクトを作成し、最初の参考画像を投入する。
2. ComfyUIで参考画像をタグ付けする。
3. タグから設定枚数の候補画像を生成する（初期想定10枚）。
4. 各画像について「好き」「嫌い」「未評価」のいずれかを選ぶ。好き／嫌いの合計は最低1枚必要。複数選択可能。
5. 同世代の好き画像群・嫌い画像群からタグ差分を計算し、前回の条件を50%の重みで継承する。
6. 新たな乱数seedで次の候補群を生成し、全画像をタグ付けする。
7. 完成したGenerationを保存し、画面最下部へ追加する。ユーザーが任意に終了するまで反復する。

## 3. タグ集計・プロンプト更新

- 好き画像群のみに現れるタグ: positiveの維持・強化候補。
- 嫌い画像群のみに現れるタグ: positiveからの除去、またはnegativeへの移動候補。
- 両群に共通のタグ: 原則として維持・判断保留。
- 出現頻度を集計し、前回までの条件50%と今回の評価結果50%を合成する。
- 「嫌い」だけ選ばれた場合も処理を継続できる設計とする。
- 削除・negative化の判定、重み計算法は実画像を見ながら決定する。現段階では独自の高度な探索制御を必須にしない。
- seed等による自然なばらつきを利用し、同じ条件・選択からも別画像を生成できるようにする。

**タグ取得:** V1の `SaveText` → TXT再取得を廃止し、ComfyUIの実行履歴に現れるWD14Tagger等の出力を直接読む。タグごとの確率取得は将来の検証課題であり、初期実装ではタグ文字列を扱う。将来のスコア付与に対応できるJSON構造にする。

## 4. プロジェクトと履歴

- プロジェクトは最初の参考画像から始まるGenerationの集合。
- Generation履歴は**木構造**。任意の過去世代から分岐し、既存の枝は消さない。
- Generationには「その世代で生成された画像と各画像のタグ」と「実際の画像生成パラメータ」を保存する。
- **子Generation**は、それを生成する際に用いた**親画像への好き／嫌い選択**をスナップショットとして持つ。親Generation自体は書き換えない。
- 選択途中の状態、生成途中の状態はDBに保存しない。
- 画像生成と全画像のタグ付けが完了した後、Generationと画像情報を**単一トランザクション**で登録する。
- DBに残るGenerationは完成品だけ。ファイルとDBの整合性は別途ステージング・清掃で担保する。

## 5. データベース

SQLiteで以下の3テーブルを基本とする。

| テーブル | 役割 |
|---|---|
| `projects` | プロジェクトID、名前、最初の参考画像など |
| `generations` | 親ID、親画像への選択JSON、使用パラメータJSON |
| `images` | Generation ID、画像ファイル、表示位置、seed、タグJSON |

生成画像のタグは `images.tags_json` にまとめ、`image_tags` は作らない。選択は子Generation内で保持するため、`selections` と `selection_items` も作らない。`images.position` は0以上とし、固定10枚上限を設けない。詳細は [schema.sql](../sql/schema.sql)。

## 6. 技術構成

| 区分 | 技術と責務 |
|---|---|
| Backend | Python / FastAPI：ComfyUI連携、タグ集計、履歴保存、起動・終了制御 |
| Frontend | React / TypeScript：画像アップロード、一覧、好き・嫌い評価、履歴・枝切替 |
| UI | Chrome：主に1920pxのフルスクリーンデスクトップ利用 |
| DB | SQLite：完成Generationのみ永続化 |
| 生成エンジン | ComfyUI API：タグ付け、Stable Diffusion画像生成 |

FastAPIが立ち上がったらChromeを自動起動する。SSE接続切断でUI終了を検知し、再読み込み等の一時切断を除外した上でバックエンドも終了させる。

## 7. UI

- チャットのように、新しいGenerationを画面下に追加して縦スクロールで閲覧する。
- 上へスクロールすれば、それまでの選択や候補を自然に振り返れる。
- 各Generationは画面幅を広く使う。1画面2Generationは目安に過ぎず、高さ固定はしない。
- 画像数・アスペクト比に応じてレイアウトを自動調整。過去閲覧中に勝手に最下部へ戻らない。
- 木構造の別の枝への切り替え手段を用意する。

## 8. 設定・対象外

- 一度の生成枚数はコンフィグ可変（初期想定10）。
- 幅・高さ（アスペクト比）はコンフィグ可変。過去Generationには使用時の値を残す。
- アップスケール、高解像度仕上げ、終了条件・収束判定、独自画像生成モデルは対象外。

## 9. 開発方針

**人間の手打ちコード0行。** アプリ本体、SQL、設定、テスト、CI/CD等の実装・修正はAIが行う。人間は目的と優先順位、仕様の決定、実機検証、完成判定を担う。V1は機能比較の参考とし、設計の無批判な移植はしない。

## 10. 保留・実機で確かめる点

- タグ推定確率の取り出し方。
- 50%継承とpositive/negative移行の正確な数式。
- ComfyUIの履歴APIから取得できる結果形状。
- Chrome終了検知の例外・再接続の挙動。
- 分岐表示UI、ファイルの配置・削除・失敗復旧の実装方法。
