# 工程16 自動検証・配布準備／工程17 人力受入確認

## 起動に必要な環境

Windows、Python 3.12以上、Google Chrome、起動済みComfyUIが必要です。
ComfyUIにはCheckpointLoaderSimpleで利用できるチェックポイントとWD14Tagger
（wd-v1-4-moat-tagger-v2）が必要です。初回生成はモデル一覧の先頭を使用します。
モデルやカスタムノードはアーカイブに同梱しません。

## 配布準備

AIがUIをビルドし、`python -m scripts.prepare_distribution` を実行すると
`artifacts/LoopImageGeneratorV2.zip` にPythonソース・ビルド済みUI・DDL・設定・
依存一覧・この確認表をまとめます。既存ZIPの上書きは拒否します。
保存データ・仮想環境・秘密設定・Node.js依存は含めません。
これは配布候補の最小実行構成で、実行ファイル化などの最終配布方式は保留です。

展開先でAIがPython仮想環境を作り、`requirements.txt` の依存を導入します。
AIがComfyUI URLと保存先を設定し、`.venv/Scripts/python -m backend.launcher`
で起動します。ビルド済みUIを含むため、利用時のNode.jsは不要です。
ソースリポジトリでの開発・全テスト手順は [README](../README.md) を参照してください。

## 工程16 自動受入検証

AIがリポジトリで次を実行します。一時DB・画像保存先を使用し、実データを変更しません。
ComfyUIには検証用の送信画像と生成出力が残ります。

```powershell
.venv/Scripts/python -m scripts.check_acceptance
.venv/Scripts/python -m scripts.check_lifecycle
.venv/Scripts/python -m scripts.check_recovery
```

受入スクリプトは実ComfyUIと1920×1080のヘッドレスChromeを使用し、
参考画像のUI投入、2枚の初回生成、好き／嫌いを使う子生成、タグ50%継承の計算結果、
未確定評価で保存履歴が変わらないこと、API再起動後の再開、設定を3枚・横長へ変更して
同じ親から分岐、既存枝の不変性、両枝の再開、保存画像の寸法・枚数・seed更新を確認します。
ライフサイクル検証はChrome自動起動・再読み込み・複数タブ・最終タブ終了・強制終了時の
バックエンド停止を確認します。復旧検証は固定生成結果で更新・重複送信・巨大履歴を確認します。

## 工程17 人間による表示ウィンドウの受入

コード・SQL・設定の手打ち修正は不要です。AIが設定・起動を担当し、人間はUIを操作します。

| 操作 | 確認する結果 |
|---|---|
| トップの新規作成リンクから作成ページへ移動 | トップに作成フォームがなく、作成ページで名前・モデル・画像サイズを選べる |
| 設定でモデルの許可と追加画像サイズを変更して保存 | 新規作成の選択肢へ反映され、再起動後も保持する。固定3サイズは削除できない |
| モデル・サイズを選んで作成し、初回・次世代を生成 | 選択したモデル・サイズで生成し、世代の生成条件にも記録される |
| 設定へ移動し、ブラウザで戻る・進む | 設定ページと直前のページを切り替えられる |
| 個別ページを再読み込み | 同じプロジェクトの履歴を再表示する |
| 不要なテスト用プロジェクトを削除（キャンセル後、確認して削除） | キャンセルで残り、確認後は所属履歴・画像ごと消える。他のプロジェクトは残る |
| 生成中のプロジェクトを削除 | 拒否され、生成処理と保存済み履歴が維持される |
| 新規プロジェクトを作り、画像を選択またはドロップ | 参考画像が表示される |
| 初回生成を開始 | 設定した枚数・縦横比の候補が表示される |
| 好き／嫌いを選択、同じボタンを再クリック | 排他的な評価と解除ができる |
| 評価を確定して次世代生成 | 子世代が追加され、選択履歴が表示される |
| 過去世代から再度生成し、枝を切替 | 既存枝と新しい枝の両方を開ける |
| 上の世代を閲覧したまま生成完了を待つ | 閲覧位置が維持される |
| ページを更新し、プロジェクトを開く | 完成済み履歴が再表示される |
| 専用Chromeを閉じる | 最終接続切断から設定した猶予後にAPIが終了する |
| 再起動して両枝を開く | 保存済み画像・評価履歴が維持される |

工程16は自動検証・配布準備までを完了しています。工程17の人力受入検証は未実施です。確認結果が得られるまではロードマップ17を完了扱いにしません。
タグ式は暫定、タグ確率取得・外部削除画像の復元・無制限履歴の性能保証・
実行ファイル化は未対応です。アップスケール等の対象外機能は追加していません。
